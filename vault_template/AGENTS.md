# AGENTS.md — 이 위키 보관소의 규약 (Codex, Claude Code가 읽는다)

이 폴더는 연구 문헌 **LLM Wiki**다. 읽은 논문의 요약·해석·연결을 마크다운으로 쌓는다.
AI는 사서(요약 초안, 연결, 목록, 점검)를 맡고, 판단은 사람(Contribution, Caveats, 내 연구와의 관계)이 한다.
Obsidian으로 열어 본다. 이 폴더에서 AI를 열면 이 문서를 먼저 따른다.

## 규칙
1. **서지(제목·저자·연도·학술지·DOI)는 고치지 않는다.** 프로그램이 수집한 값이 기준이다.
2. **사람 섹션**(제목에 `(사람)`이 붙은 3개): `<!-- llm-draft -->` 표식이 있으면 AI 초안이다. 사람이 고쳐 쓰고 표식 줄을 지우면 그 섹션은 사람 것이 되어, AI는 다시 쓰지 않는다.
   사람이 세 섹션을 다 다듬었다고 하면 frontmatter `human_sections_done: true`, `status: read`로 바꾼다.
3. 단정은 근거가 있을 때만 쓰고, 주장 끝에 (PDF p.N) 또는 (초록)을 붙인다. PDF 쪽 번호는 `raw/text/`의 `=== PDF p. N ===` 순번이다.
4. 인용문은 원문 그대로 15단어 이하, 한 페이지에 2개까지.
5. 링크는 `[[인용키]]`, `[[개념-이름]]`. 실제로 있는 페이지만 링크한다.
6. 개념 페이지 이름은 영문 소문자와 하이픈(`hedonic-pricing`). 같은 개념을 두 번 만들지 않는다(`index.md`의 개념 목록을 먼저 본다).
7. 문체: 한국어. 고유명사·변수명·통계 용어는 원문. 과장 형용사를 쓰지 않는다.
8. `index.md`는 손으로 고치지 않는다(`python wiki.py index`가 다시 만든다). 작업을 했으면 `log.md` 끝에 `## [YYYY-MM-DD] 종류 | 대상`과 바꾼 파일을 덧붙인다.

## 논문 페이지 쓰기 (자동 작업과 같은 기준)
- 형식은 `wiki/_templates/source.md` 그대로. 섹션: 사람 3개 → Research Question → 연구 방법론 → 주요 결과 → 저자가 밝힌 한계 → 미래 연구 → 관련 논문 → 인용문
- PDF가 없으면 초록만으로 쓰고, 초록에 없는 내용은 "초록에 없음"이라고 쓴다. `read_scope: 초록만`
- PDF가 생기면 다음 아침 자동으로 본문 기준으로 다시 쓴다(사람이 쓴 섹션은 그대로 둔다).

## 사람이 부탁할 때 하는 일

### "질문: …" 또는 "…에 대해 위키에서 찾아줘"
1. `index.md`에서 후보 페이지 3~10개를 고르고 읽는다. 필요하면 `raw/text/`의 원문을 찾아본다.
2. 위키 페이지를 근거로 답한다. 문장마다 [[인용키]]를 단다. 위키에 없는 내용은 "위키에 없음"이라고 구분한다.
3. 사람이 "저장"이라고 하면 `wiki/syntheses/s-이름.md`(비교·정리) 또는 `wiki/questions/q-이름.md`(연구 질문)로 템플릿대로 만들고 log.md에 기록한다.

### "점검해줘"
깨진 링크, 고아 페이지(어디서도 링크 안 됨), 사람 섹션 미작성, 초록만 읽은 논문, 중복 개념을 찾아 목록으로 보여 준다. 고치기 전에 사람에게 확인받는다.

### "이 논문 다시 써줘" / "PDF 넣었어"
`raw/pdf/인용키.pdf`가 있으면 사람에게 `python wiki.py ingest --key 인용키`를 실행하라고 안내하거나(프로그램 폴더에서), 직접 위 '논문 페이지 쓰기' 기준으로 다시 쓴다. 사람 섹션은 건드리지 않는다.

### "개념 정리해줘: X"
X를 다루는 논문 페이지를 모아 `wiki/concepts/x.md`의 '문헌에서의 쓰임'을 논문별 한 줄로 채우고, 상충하는 정의나 결과는 '쟁점'에 쓴다.

## 하지 말 것
- `inbox/alerts/`의 체크박스 말고 다른 내용을 고치지 않는다.
- 출판사 웹페이지를 긁거나 유료 PDF를 내려받지 않는다.
- API 키나 비밀번호를 파일에 쓰지 않는다.
